# Phase 27 证据 — OCB=16 档：幂律在 8 之后断裂，且断裂点随 C 变号（已按预登记回退）

本机：Windows 11 + MinGW + AMD **RX 6600M（gfx1032）**，ROCm 7.1。日期 2026-10-28。
预登记全文在 `task_plan.md` 的"Phase 27 预登记"；判据先写死后才跑，`ocb16-sweep.txt` 头部就是那次写死的四行。

## 为什么测这一条

Phase 23/24/25 关闭了三种解释（X 复用度、LDS bank、occupancy）之后，唯一还活着的量纲是
**OCB 的幂律**（Phase 25 钉住矩阵，tile=16，256²：1/2/4/8 → 31.571 / 18.079 / 10.515 / 7.129 ms）。
局部指数 β = log2(t(k)/t(2k)) 依次是 **0.803 / 0.781 / 0.561**——成立但在衰减。
加一档 OCB=16 就是把这条外推**推到会被否证的地方**：预登记写死了两个分支，
① 16 档 ≤ 5.97 ms ⇒ "取数指令数受限"继续成立；② 16 档反而慢于 8 ⇒ 天花板是每线程寄存器/ILP，
"再加大 OCB"这条路就此关死。

## 实测（`ocb16-sweep.txt`，全部 `verify=PASS max_rel=0.000000e+00`）

| 形状（tile=16 钉住） | ocb=8 | ocb=16 | 16 相对 8 |
|---|---|---|---|
| 256²×32 / Oc64（三次：8,16,16） | **7.160519** ms | 7.858002 / 7.854852 ms | **慢 9.7%**（两跑相差 0.003 ms，重复性极好） |
| 128²×16 / Oc32 | 0.288485 ms | **0.266870** ms | **快 7.5%** |

自动档（候选集含 16 时）：256² 选中 `ocb=16 tile=16` → 7.833645 ms（**比它本该选的 8 档慢 9.4%**）；
128² 选中 `ocb=16` → 0.262671 ms（更快）；32² 仍 `ocb=1 tile=0` → 0.014936 ms（其分布上沿附近）。

## 判定

- **保留线判负**（预登记的判据只绑 256²：`≤ 5.97 ms`）→ 走**分支②**：幂律在 8→16 之间**断裂并反号**，
  与 Phase 23 微块同签名（活跃累加器 8→16 时开始付寄存器代价）。
  按规则回退；`postrevert-confirm.txt`：256² **7.156521**、128² **0.284850**，选档器重新选中 `ocb=8`，
  发射程序与 `docs/evidence/phase26/conv-hip-single-plan.txt` **`diff` 空**（517 行，第三次用这条举证）。
- **但真正的新事实不是"16 更差"**，而是**同号不成立**：16 档在 C=32 上慢 9.7%、在 C=16 上快 7.5%。
  ⇒ **最优 OCB 是 (C, Oc) 的函数**，"越复用越好"这条编码在选择器里的单调偏好**被测量推翻**。
  本轮因此不能改成"16 更好就留 16"：那需要一个按 C 的分档规则，而证据只有两个点（每个 C 各一个形状）。
  本项目对选择规则的要求一直是**由设备自报量推导、不写死拟合出来的阈值**
  （`findings.md` Phase 20 段第 604 行那条），两点定不出这种规则，所以不动选档器。
- **选档器现在会选错**（256² 上选 16 慢 9.4%），这是保留 16 档的独立否决理由：
  规则里没有计时信息，加一档只会把错误偏好带进 shipping 路径。

## 下一手（靶，不是决定）

要把"最优 OCB 随 C 变号"变成可用的选择规则，缺的是**统计量而不是想法**：
固定 tile=16，扫 `C ∈ {8,16,32,64} × ocb ∈ {8,16}`、每个组合 ≥3 跑，看符号翻转发生在哪个 C、
以及它是否与 `Oc/C` 的比值一致。这属于另一相（Phase 28）的测量内容；
在那之前 conv 的现役读数仍是 Phase 21 的 `tile=16 / ocb=8`：256² 337.5 GFLOPS、128² 524.9 GFLOPS。
