=== verdict (written after the runs, criteria checked in order) ===
1. keep-line MISSED: 256^2 = 7.135740 / 7.145340 ms, i.e. inside the unpadded band 7.1276-7.1750 (change < 0.5%,
   smaller than the run-to-run spread). Padding C->C+1 bought nothing at C=32.
2. discriminating control NOT satisfied as a support signal: 128^2 = 0.302160 / 0.295439 ms vs unpadded 0.287 ms
   is 2.9-5.3% *slower*. Neither shape improved, so the "conflict factor scales with C" prediction got no support.
3. negative control MOVED: 32^2 was tile=0/smem=0 ("nothing fills the device"), it is now tile=8/smem=3600
   ("fills=device") and 0.016357 / 0.020372 / 0.015565 ms against 0.010700 / 0.013381 / 0.013040 ms unpadded
   (1.5x slower). Cause is structural, not accidental: uk_conv_plan feeds cand.smem into the occupancy probe and
   accepts a candidate on `threads >= per_cu * multiProcessorCount`, so *any* change to the smem formula changes
   which plan is accepted. Therefore a layout-only A/B is not observable through this chooser at tiny shapes.
4. accumulation order held: 6 result lines + 1 trace line, max_rel = 0.000000e+00 in every one.
