1. 执行摘要

UNIKERN 的使命是：把物理 GPU（NVIDIA / AMD / Intel）抽象成统一的中间表示，让内核可跨厂商复用； 把"针对硬件定制内核"从手工艺变成可求解的数学优化问题；并支持在硬件到手之前完成大部分开发工作（AOT 预开发）、 CPU+GPU 并行与统一内存。

关键诚实点（先泼冷水）： "一个数学问题只有一个最优解"在真实 GPU 调优中并不成立。WaveTune（2026）对 GPU 内核延迟地形的实测证明： 性能地形是非凸的，且在寄存器 / 共享内存 / 缓存容量边界处呈离散跳变——不存在连续优化意义上唯一的全局最优。 任何宣称"自动找到真实硬件全局唯一最优"的系统都是在自我欺骗。
因此本设计的核心巧思是改写命题：不追求"真实时间意义上的唯一最优"， 而是把问题分解为 （a）多面体约束刻画的可行域 F ＋ （b）确定性解析代价模型 C 作为唯一仲裁者。 固定 (F, C, 字典序) 三元组后，求解过程是一个纯函数：同输入必产生同一输出解， 唯一性、可复现性、可审计性在数学上成立。搜索器（Ansor 式枚举 + LLM 引导）只负责探索残差子空间， 最终排序与选择权归 C；C 与真实时间的偏差由实测闭环（L4）校准并给出误差上界。 这是"唯一最优"在工程上唯一站得住的形态。
交付形态：七层架构（L0 情报 → L1 抽象 → L2 数学表示 KML → L3 求解器 → L4 闭环 → L5 AOT → L6 异构运行时与多级存储）， 配架构图、优化闭环图、唯一最优解形式化、技术选型与风险清单。 明确不做的事：不翻译 CUDA（法律红线，见 §9）。

2. 问题定义与目标

编号目标良定义化
O1跨厂商内核复用物理 GPU → 厂商中立统一计算模型 UCM；内核以数学对象（tile / layout / 原语树）表达，与 ISA 无关
O2定制 = 数学优化定制问题归约为：在可行域 X 上最小化确定性代价 C(x)，固定 (X, C, 字典序) 后解唯一确定
O3提前获取 GPU 情报做 AOT 开发持续情报流（发布前规格、SDK 节奏、ISA 文档）→ 硬件能力规格 HCS → 新卡宣布即触发预开发，上市即加载预缓存配置
O4CPU+GPU 并行与多级存储任务图分区 + 双缓冲重叠；覆盖全谱系硬件：传统离散 GPU（显存 + RAM + NVMe 盘的显式拷贝与流式预取）、小显存 out-of-core 分层驻留、物理统一内存（Grace Hopper / MI300A）与 CXL 远内存；放置与预取决策统一进 C 求解

非目标（明确排除）

  • 不翻译 CUDA 源码 / PTX 到其他后端——NVIDIA EULA 禁止逆向翻译，ZLUDA 的先例证明该路线法律上不可持续。KML 独立生成各后端代码。
  • 不承诺"真实硬件时间全局唯一最优"（见 §1 诚实点），只承诺"良定义数学意义上的解唯一确定 + 实测校准的误差上界"。
  • 不在硅前做 ISA 级调优——ISA 微调只能在硬件到手后进行，AOT 的边界在"后端 IR 级"。

4. 总体架构：七层设计

七层自下而上逐层剥离物理 GPU。核心原则有三：① 翻译禁令——各后端代码从 KML 独立生成，不经 CUDA； ② 仲裁唯一——任何搜索/学习组件都无最终裁决权，裁决权归确定性解析代价模型 C； ③ 情报先行——硬件到手前，L0 情报流已驱动 L5 完成大部分开发。

5. L0–L2：情报、抽象与数学表示

L0 — GPU 情报层

  • 源与优先级：thegpu.guru（结构化 GraphQL，首选）→ TechPowerUp（全量覆盖交叉验证）→ 厂商官方 ISA/SDK 文档（权威）→ MLPerf（实测上界参考）。
  • 归一化产物 HCS（硬件能力规格）：计算单元数与频率域、SIMD/带宽逐层表、缓存/寄存器容量、张量原语族吞吐表（MMA / MFMA / XMX）、存储与互联层级表（显存 / PCIe / RAM / NVMe 盘 / CXL：带宽、容量、介质类型）、后端 IR 目标与工具链版本。每字段带置信度标记（官方文档 > 实测数据库 > 发布前预测）。
  • 触发机制：新卡宣布事件 → 生成草稿 HCS → 驱动 L5 预开发；零售上市后用首轮实测回填修正置信度。

L1 — 硬件抽象层（统一计算模型 UCM）

  • 物理 GPU 折叠为厂商中立的 UCM：SIMD/warp 形状、存储层级树、张量原语族、同步原语四类抽象面。
  • 原语族不对齐时（如 NVIDIA mma.sync 形状 vs AMD MFMA 形状 vs Intel XMX）采用分层退化：UCM 定义抽象原语能力区间，后端选择最接近实现；无法覆盖时该区间对 KML 标记为"后端不支持"，进入 L3 可行域约束——不支持即不可行，绝不静默降性能。
  • 后端目标：PTX（NVIDIA）、RDNA/CDNA ISA（AMD）、SPIR-V / Level Zero（Intel）。三者均由 KML 独立生成，无 CUDA 派生关系。

L2 — 数学内核表示 KML（MLIR Dialect）

  • 原子对象 = tile（借鉴 CUTLASS CuTe）：tile 尺寸、stride、layout、swizzle 均为一等数学对象，可参与代数运算与等价推理。
  • 内核 = 可组合原语树：GEMM = [加载 → 布局变换 → 张量原语 → 归约 → 写回] 的结构化树；"从低到高自动组合"即在该树上做类型化重写。
  • 合法性 = 多面体约束：依赖无冲突、tile 整除性、别名分析、容量约束统一表达为整数不等式组，交给 L3 的多面体引擎判定（isl / Farkas）。
  • KML 编译为 MLIR Dialect，复用 MLIR 的 lowering 基础设施到达各后端 IR。

6. L3：求解器与唯一最优解的形式化

6.1 数学定义

// 决策空间与可行域 P = { x | x 为 KML 原语树在有限参数格（tile 尺寸、重排、swizzle…）上的实例 } // 有限集 F(x): 整数不等式组（多面体）— 缓存/寄存器容量 ≤ HCS 上限 · tile 整除 · 无依赖冲突 · 原语能力覆盖 X = { x ∈ P | F(x) 可行 } // 由 isl / Farkas 引理判定，非空才进入搜索 // 确定性解析代价模型（唯一仲裁者） C(x) = max( 算力项 Σ ops/primitives(x), 带宽项 Σ bytes/bw(盘·RAM·互联·显存), 延迟项 lat_tree(x) ) // 分层 roofline 展开（含盘 → RAM → 互联 → 显存全层级）；所有常量来自 L0 的 HCS；无随机性、无学习参数 // 决策变量除内核参数外，还包括：数据放置层、数据通路、流式分片粒度与预取距离 d —— 放置即求解 // 唯一最优（良定义版本）：字典序，代价为主键，结构规范化为次键 x* = argmin over X of ( C(x), canonical_form(x) ) lexicographic

6.2 命题一（可复现唯一性）

若 (i) C 为确定性函数（对同一 x 恒返回同一值），(ii) X 有限且非空，(iii) 采用字典序 (C, canonical_form) 为严格全序—— 则 argmin 存在且唯一；求解器 solve(F, C, X) → x* 是纯函数： 同输入必得同解，可审计、可复现、可增量改进（C 更新即得新确定解）。 唯一性不依赖搜索器——搜索器只是 x* 的加速逼近器，任何搜索改动不影响解的定义，只影响收敛速度。

6.3 命题二（与真实最优的差距，诚实边界）

// 设真实硬件时间为 T(x)，C 的保真度界为 ε： if | T(x) − C(x) | ≤ ε for all x ∈ X, then | T(x*) − minx∈X T(x) | ≤ 2ε // x* 是高保真代理解，非真实唯一最优 ε 由 L4 实测闭环校准：每次实测回报 (x, T(x)) → 修正 C 的层级常量 → ε 单调收紧
为什么必须这样改写：WaveTune（2026）已证明 T 的地形非凸且在容量边界离散跳变—— "对 T 做全局优化并宣称唯一最优"既不可判定也不可复现。把唯一性建立在 (X, C, 字典序) 这个 完全可控的良定义对象上，工程上得到：确定性、可审计、误差有界、随校准单调逼近真实最优。 这是该命题在现实中站得住的唯一形态。

7. L4–L6：闭环、AOT 与多级存储运行时

L4 — 自动开发·测试闭环 + Kernel Solution Ledger

  • 正确性：差分测试（KML 生成实现 vs 参考实现，多精度位级/容差比对）+ 数值等价边界用例（极角、非结合浮点路径标注）。
  • 性能：固定基准协议（预热、多次采样取中位数、时钟锁定），结果写入 Kernel Solution Ledger（解账本）。
  • Ledger 键：(算子签名, 输入形状域, HCS 指纹, KML 原语树哈希) → 值：(解 x*, 实测 T, C 误差记录)。
  • 命中语义：新请求若 Ledger 命中则直接返回解并按 HCS 指纹适配——"适配最快"路径，跳过 L3 全部搜索（图 2 绿色虚线）。
  • 校准语义：未命中走完整闭环；实测结果回写 C 的层级常量，ε 随数据量单调收紧（图 2 橙色回路）。

L5 — AOT 提前开发

  • 流程：新卡宣布 → L0 草稿 HCS → KML→后端 IR 预编译 + 预测最优配置预缓存 → 上市即加载。
  • 诚实边界：预开发只能到达"后端 IR 级 + 预测配置"；ISA 级微调（调度器形状、bank conflict、occupancy 精调）必须留待硅后，由 L3 在真机上以小预算重调完成。宣称"硅前全量调优"是不诚实的。
  • 置信度传播：草稿 HCS 的置信度随预编译产物传递，上市后首轮实测校验；偏差超阈值则触发重新求解。

L6 — 异构运行时 + 多级存储（覆盖全谱系硬件）

统一内存只是内存问题的一个特例。UNIKERN 将 L6 建模为通用的多级存储放置与调度问题， 同一套求解器覆盖三类硬件形态，差异只在 HCS 的层级常量：

场景 B · 传统离散 GPU

含「小显存 + 大内存 + 大硬盘」		通用主场景，三个机制：
① 显式拷贝调度：pinned memory + 双缓冲，copy engine 拷贝与 SM 计算流水重叠；
② 显存不足的流式执行（out-of-core）：以 tile / layer / 权重分片为粒度分层驻留（显存 → RAM → 盘），驻留策略与预取距离由 C 求解——计算当前块时预取下一块；禁止隐式显存超订缺页（UVM oversubscription 经 PCIe 缺页迁移性能塌陷，宁可显式流式）；
③ 盘层级：mmap 权重流与 GPUDirect Storage 直读显存作为候选数据通路（由 C 择优），盘带宽与队列深度进入 C。
场景 C · 扩展内存层
CXL 远内存 · HMM/SVM		容量兜底与厂商中立路径：CXL 的额外延迟层级计入 C 参与放置决策；HMM/SVM 作为 Intel / 开源栈的页表一致性基座。
图 3 — 多级存储层级与数据通路。左侧：层级带宽/容量谱；中部：传统离散 GPU 的流式通路（双缓冲 + 预取 + 盘直读）；右下：物理统一内存平台作为零拷贝特例。放置层、数据通路、流式分片粒度与预取距离 d 全部由 C 统一求解。

统一原则——放置即求解：数据放置层（驻留在显存 / RAM / 盘）、数据通路（显式拷贝 / GDS 直读 / 零拷贝）、 流式分片粒度与预取距离、CPU/GPU 任务图切分，全部编码为决策变量进入同一 (X, C, 字典序) 框架。 统一内存不是独立特性，而是 C 在互联层带宽趋于极大时的自然解（零拷贝）； 小显存不是异常，而是 C 在显存容量约束收紧时自动给出的流式调度解。三场景共用同一求解器，不引入第二套启发式。

9. 风险清单与诚实边界

编号风险 / 边界应对
R1法律红线：翻译 CUDA 违反 NVIDIA EULA（ZLUDA 先例）架构级规避：KML 独立生成三后端，零 CUDA 派生；全员禁触翻译路线
R2C 保真度不足：真实地形非凸 + 容量边界离散跳变（WaveTune 2026），C 排序与实测局部倒序top-k 实测兜底 + 校准回路收紧 ε；对外话术永远是"误差有界的代理解"，绝不宣称真实唯一最优
R3ISA 硅前未知：调度器微架构细节无法预知AOT 边界限定在"后端 IR 级 + 预测配置"；ISA 级留给上市后 L3 小预算重调
R4张量原语族不对齐（mma.sync / MFMA / XMX 形状差异）UCM 能力区间 + 分层退化；不覆盖即不可行（进 F），绝不静默降级
R5发布前情报噪声：规格泄露/预测置信度参差HCS 置信度分级；预开发产物按置信度标记；上市首轮实测强制校验
R6LLM 提名质量不稳定，可能引入无效候选浪费预算LLM 输出必须过 F 可行性判定 + C 认证；无效提名只影响收敛速度，不影响解的正确性与唯一性
R7三厂商工具链版本漂移（PTX / RDNA / SPIR-V 语义变化）后端目标绑定工具链版本指纹，进入 Ledger 键；漂移触发重算
R8隐式显存超订：UVM 缺页迁移经 PCIe 性能塌陷，掩盖真实放置错误架构级禁用隐式超订；显存不足一律显式流式（分片 + 预取距离由 C 求解）；运行时监测缺页率，超阈值告警并触发重求解
R9存储介质异构：HDD / SATA SSD / NVMe 带宽差一个数量级以上，预取参数不可移植HCS 存储层档位化（介质类型、带宽、队列深度）；预取解按 HCS 指纹进入 Ledger，介质变化触发重算
